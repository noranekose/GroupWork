# AIを使いこなす技術

# 〜AgentとSkillとは？〜

---

# 1. Agentとは

Agentとは、

AIが自律的に「考え・判断し・行動する」
仕組みのこと。

単に質問に答えるだけでなく、

**目標を与えると、自分でタスクを分解し、
ツールを使いながら実行する。**

---

## 従来のAIとAgentの違い

### 従来のAI（チャット）

```txt
人間: バグを修正して
AI:  こう直せばいいと思います（提案のみ）
人間: じゃあファイルを修正して
AI:  このコードに変えてください（まだ提案）
人間: （自分でコピペして修正する）
```

---

### Agent

```txt
人間: バグを修正して
Agent: ファイルを読む → 問題箇所を特定 →
       修正を加える → テストを実行 →
       結果を報告（自律実行）
```

---

# 2. Agentの動き方

Agentは以下のループで動く。

---

## Think → Act → Observe

```
① Think   : 次に何をすべきか考える
② Act     : ツールを使って行動する
             （ファイル読む・コード実行・検索）
③ Observe : 結果を見て次の行動を決める
④ 繰り返し → 目標達成まで続ける
```

---

## 使えるツールの例

* ファイルの読み書き
* コードの実行
* Webの検索
* コマンドの実行
* 外部APIの呼び出し

---

# 3. Agentを支える「スコープ」

Agentは、以下の情報をもとに判断する。

---

## Agentが参照する情報

| 情報        | 内容                       |
| ----------- | -------------------------- |
| 指示        | ユーザーからのタスク       |
| CLAUDE.md   | プロジェクトのルール・背景 |
| ファイル    | コードや設計書             |
| Skill       | 特定作業の手順書           |
| 実行結果    | ツール使用の結果           |

---

# 4. Skillとは

Skillとは、

**Agentに特定の作業手順を覚えさせる
「仕事マニュアル」**。

Agentが同じ作業を毎回うまくこなせるよう、
手順・制約・出力形式をあらかじめ定義しておく。

---

## Skillがない場合

```txt
人間: コードレビューして
Agent: （何を見ればいいか自分で判断）
       → 視点がバラバラ
       → 出力形式が毎回変わる
       → 重要観点の見落とし
```

---

## Skillがある場合

```txt
人間: コードレビューして
Agent: （Skillを参照）
       → 観点①: セキュリティ
       → 観点②: パフォーマンス
       → 観点③: 可読性
       → 決められた形式で出力
```

---

# 5. Skillの構成

Skillは **Markdownファイル** で定義する。

---

## 基本構成

```markdown
---
name: code-review
description: コードレビューを行うスキル
---

# コードレビュースキル

## 確認観点
1. セキュリティ
2. パフォーマンス
3. 可読性

## 出力形式
- 問題点を箇条書き
- 深刻度を3段階で表示
```

---

# 6. AgentとSkillの関係

---

## 全体像

```
ユーザー
  ↓ タスクを依頼
Agent（Claude Code）
  ↓ 作業の種類を判断
Skill を選択・参照
  ↓ 手順に従って実行
ツール（ファイル・コマンド等）
  ↓ 結果を観察
Agent → 完了まで繰り返す
```

---

## 例：コードレビューの流れ

```
① ユーザー: 「このPRをレビューして」
② Agent: コードを読む（ファイル参照）
③ Agent: code-review Skill を参照
④ Agent: Skillの観点でチェック
⑤ Agent: Skillの形式で結果を出力
```

---

# 7. Skillの種類

---

## 用途別のSkill例

| Skill名       | 用途                     |
| ------------- | ------------------------ |
| code-review   | コードレビュー           |
| brainstorm    | 設計の壁打ち             |
| git-commit    | コミットメッセージ生成   |
| doc-writer    | ドキュメント作成         |
| test-gen      | テストコード生成         |

---

## チームで共有できる

Skillファイルをリポジトリに入れることで、

**チーム全員が同じ品質・観点で
Agentを使える。**

---

# 8. SubAgentとは

複雑なタスクは、

**Agentが自分でAgentを呼び出す**
「SubAgent」の仕組みも使える。

---

## SubAgentのイメージ

```
メインAgent
  ├─ SubAgent A（設計レビュー担当）
  ├─ SubAgent B（セキュリティチェック担当）
  └─ SubAgent C（ドキュメント作成担当）
```

大きなタスクを分担して並行処理できる。

---

# 9. 実践編

# Skillを使ったコードレビュー

---

## Skillなし（コンテキスト不足）

```txt
◎ レビューして
```

Agentは、

* どんな観点で見ればいい？
* どう出力すればいい？
* どこまで指摘すればいい？

を自分で推測するしかない。

---

## Skillあり（コンテキスト充実）

```markdown
# code-review Skill

## 背景
チームのコードレビュー品質を統一する

## 確認観点（必須）
1. セキュリティ（SQLインジェクション・認証）
2. パフォーマンス（N+1・不要なループ）
3. 可読性（命名・コメント・複雑度）

## 出力形式
| 深刻度 | 場所 | 問題 | 修正案 |
| ------ | ---- | ---- | ------ |

## 制約
- 軽微な指摘は省略する
- 修正案を必ず添える
```

---

# 10. 比較

| Skillなし                  | Skillあり            |
| -------------------------- | -------------------- |
| 観点がバラバラ             | 観点が統一される     |
| 出力形式が毎回変わる       | 出力形式が安定       |
| 重要点の見落としあり       | 漏れなくチェック     |
| 個人差が出る               | チームで品質統一     |

---

# 11. 重要な考え方

Agentを使いこなすには、

---

# 「何をやらせるか」

だけではなく、

# 「どんな手順で・どんな形式で
やらせるか」

---

を設計することが重要。

それがSkillの役割。

---

# 12. まとめ

---

## Agentとは

* 自律的に考え・判断し・行動するAI
* ファイル読み書き・コマンド実行などを自分で行う
* Think → Act → Observe を繰り返す

---

## Skillとは

* Agentに作業手順を覚えさせる「マニュアル」
* Markdownファイルで定義
* チームで共有することで品質を統一できる

---

## 設計するべきもの

* 背景・目的
* 確認観点
* 出力形式
* 制約条件

を整理してSkillに定義すること。
