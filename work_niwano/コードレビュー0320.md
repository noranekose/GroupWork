### 🔴 必須修正
> 放置するとバグ・脆弱性・ビルドエラーにつながる問題

- [ ] 【安全性】`new Function` の実行で `window`・`document`・`fetch` 等のグローバルオブジェクトへ無制限にアクセスできる。DOM 操作や `window.location` の書き換えが可能な状態。iframe サンドボックスへの移行を検討すること。（該当箇所: `runTypeScript.ts:63`）

- [ ] 【バグ】`setOutput(result.success ? result.output : result.output || '')` は成功・失敗どちらも `result.output` を設定しており、三項演算子の意図が不明瞭。メンテナンス時に誤読を招く。（該当箇所: `App.tsx:34`）

- [ ] 【可読性・バグリスク】`handleReset`（44-51行目）と `resetLessonToInitial`（53-57行目）が実質同一処理を2関数で持っている。一方を変更したときに他方の変更を忘れるリスクがある。関数を統合すること。（該当箇所: `App.tsx:43-57`）

### 🟡 提案
> 改善すると品質が上がるが、必須ではない項目

- [ ] 【可読性】`NO_LOG_PLACEHOLDER` 定数（`App.tsx:6`）と `runTypeScript.ts:76` のハードコード文字列が同一内容で分散管理されている。共通定数ファイルに切り出すべき。

- [ ] 【可読性】不合格時の `resetLessonToInitial()` + `setFailModalOpen(true)` の2行セットが3か所に繰り返されている。`handleFail()` にまとめると意図が明確になる。（該当箇所: `App.tsx:66-87`）

- [ ] 【可読性】`passModalOpen` / `failModalOpen` の2つの boolean で排他的なモーダル状態を管理している。`'pass' | 'fail' | null` の Union 型単一ステートにすると排他性をコードで保証できる。（該当箇所: `App.tsx:17-18`）

- [ ] 【パフォーマンス】`handleCodeChange` が `useCallback` でラップされていない。将来エディタコンポーネントへ置き換えた際に `React.memo` との組み合わせが効かなくなる。（該当箇所: `App.tsx:43`）

- [ ] 【テスト】`normalizeOutput.ts` はピュアな純粋関数だがテストファイルが存在しない。Vitest の導入と `\r\n`/行末スペース/空行などのエッジケーステストを追加することを推奨。（該当箇所: `src/lib/normalizeOutput.ts`）

- [ ] 【テスト】`runTypeScript.ts` の正常系・型エラー系・実行時エラー系のテストが未整備。（該当箇所: `src/lib/runTypeScript.ts`）

- [ ] 【安全性・アクセシビリティ】モーダルが開いている間、フォーカストラップが未実装。`role="dialog"` と `aria-modal="true"` は設定されているが、キーボード操作でモーダル外の要素へタブ移動できてしまう。（該当箇所: `App.tsx:185-231`）

- [ ] 【パフォーマンス】`lessons.find(...)` は現状問題ないが、レッスン数が増えた場合に備え `id -> lesson` の `Map` を事前構築すると `O(1)` 参照になる。（該当箇所: `App.tsx:20-23`）

### ✅ 良い点
> 積極的に維持・横展開してほしい実装

- `// eslint-disable-next-line no-new-func -- 学習用サンドボックス実行` と理由付きで ESLint 抑制コメントを記述している点（`runTypeScript.ts:62`）
- レッスン切り替え時に入力コードを `Record<string, string>` で保持してリセットしない設計（UX配慮）（`App.tsx:10-12`）
- `normalizeOutputForJudge` が単一責任の純粋関数として分離されており、テスト追加が容易な構造（`normalizeOutput.ts`）
- `strict: true` / `noImplicitAny: true` で学習者に厳格な TypeScript を体験させる設計（`runTypeScript.ts:25-32`）
- `aria-live="polite"` で実行結果更新をスクリーンリーダーに通知するアクセシビリティ配慮（`App.tsx:164`）
- CSS がモディファイアパターン（`.output.success` / `.output.error`）で一貫して整理されている（`App.css`）
