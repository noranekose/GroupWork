## タスク定義

### 1. テストケース設計とExcel出力

- ソースコードを読み込み、テスト対象の関数・コンポーネントを特定する
- 各対象について以下の項目を含むテストケースを設計する
  - **テストID** — `TC-001` 形式の連番
  - **テスト名** — 何をテストするかを日本語で簡潔に記述
  - **前提条件** — テスト実行前に満たすべき状態
  - **手順** — テストの操作ステップを番号付きで記述
  - **期待値** — 正常系・異常系それぞれの期待される結果
- 設計したテストケースを `work/test-cases_yyyymmdd.xlsx` に出力する（`yyyymmdd` は実行日の日付）
  - `work/` ディレクトリが存在しない場合は作成する
  - 同日付のファイルが既に存在する場合は上書きする
  - Excelはヘッダー行を固定し、1シート1対象ファイルで構成する

### 2. テストコード自動生成

- Step 1 で設計したテストケースをもとにテストコードを生成する
- Vitestでユニットテスト・統合テストを生成する
- Playwrightで主要なユーザーフローのE2Eテストを生成する
- テストは日本語の `describe`・`it` 名で記述する

### 3. テスト実行とエラー報告

- `npx vitest run` でユニットテストを実行する
- `npx playwright test` でE2Eテストを実行する
- 失敗したテストのエラー内容・原因・修正案を日本語で報告する

### 4. カバレッジ報告

- `npx vitest run --coverage` でカバレッジを計測する
- カバレッジが低いファイル・関数を特定して一覧化する
- 改善優先度（高/中/低）をつけて報告する

### 5. リグレッションチェック

- 既存テストをすべて実行し、以前は通っていたのに失敗したテストを特定する
- 変更されたファイルに関連するテストを優先的にチェックする
- リグレッションが検出された場合は影響範囲と原因を報告する

## 出力フォーマット

実行結果は必ず以下の形式で出力してください。

- すべて日本語で出力する
- テスト結果はサマリー（合格数/失敗数/スキップ数）を先頭に表示する
- 問題がある場合は「重大度：高/中/低」をつけて報告する
- 修正が必要な場合は具体的なコード例を提示する
- 結果をプロジェクトルートの `work/test-results.md` に保存する（ファイルが存在しない場合は新規作成、存在する場合は追記）
