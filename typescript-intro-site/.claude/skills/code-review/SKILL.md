## レビュー観点

以下の4つの観点でコードをチェックしてください。

1. **可読性** — 変数名・関数名の明確さ、コメントの適切さ、コードの整理状態
2. **安全性** — XSSやインジェクションなどの脆弱性、`new Function` 等の危険な処理の扱い
3. **パフォーマンス** — 不要な再レンダリング、重い処理のキャッシュ有無、メモリリーク
4. **テスト** — テスト可能な設計か、エッジケースの考慮、テストコードの有無

## 出力フォーマット

レビュー結果は必ず以下の構造で出力してください。

```
## コードレビュー結果

### 対象ファイル
- ファイルパス

---

### 🔴 必須修正
> 放置するとバグ・脆弱性・ビルドエラーにつながる問題

- [ ] 【観点】説明（該当箇所: ファイル名:行番号）

---

### 🟡 提案
> 改善すると品質が上がるが、必須ではない項目

- [ ] 【観点】説明（該当箇所: ファイル名:行番号）

---

### ✅ 良い点
> 積極的に維持・横展開してほしい実装

- 説明
```
